gg: The commit graph, without the editor.

A small, fast desktop git client built around the commit graph. See every branch at once, check out, merge, rebase and push from a right-click, work in several worktrees side by side, commit, and open pull requests, with the git you already have. Free and open source.

Opening gg the first time on macOS

gg is not notarized by Apple, so macOS stops a downloaded copy the first time you open it. Do one of these once; after that it opens like any other app. Installed with Homebrew, it opens straight away.

macOS 15+
Open gg, and choose Done when macOS says it was not opened. Then in System Settings → Privacy & Security, choose Open Anyway beside the message about gg, and confirm with your password.
macOS 12–14
Right-click gg in Applications, choose Open, then Open again.
Terminal
xattr -cr /Applications/gg.app Removes the quarantine flag macOS puts on downloaded apps. Works on every version.

What it does today

Everything here is in the current release.

Every branch at a glance

Coloured lanes, with branch, tag and stash labels on the commits they point at. Search subjects, authors and hashes, filter the graph to the branches you care about, and select a commit to see its message and changed files.

Right-click for the rest

Right-click a commit, a branch, a tag, a stash or a worktree for what you can do with it. An item that cannot run says why.

  • checkout
  • create branch
  • rename
  • delete
  • merge
  • rebase
  • cherry-pick
  • revert
  • reset
  • tags
  • stashes
  • push
  • pull
  • force push with lease
  • create worktree
  • create pull request

Every worktree, side by side

The side panel (⌘B) lists the repository's worktrees as git does, including ones made in a terminal: each with its branch, its uncommitted changes as they happen, how it stands with its upstream, and anything unusual, such as a locked worktree, a missing folder or a merge stopped there. Double-click one to make it active; every action runs there. Add a worktree for a new or existing branch, and delete one safely: anything that would be lost is listed in a red confirmation first.

Commit what you tick

The commit panel (⌘K) lists the active worktree's changed files. Tick the ones that belong in this commit, write the message, then Commit, or Commit & Push to the branch's upstream. When a merge is being concluded, its message is filled in.

Pull requests, through GitHub's gh

Create pull request… on a branch or a worktree suggests a title and description from its commits, and pushes the branch first when it needs to. Open pull requests show as markers beside their branches and worktrees. gg never reads or stores a GitHub token: gh does the signing in. Without gh, it pushes and opens GitHub's compare page.

Check out, merge, push

The everyday routine takes a few clicks: check out staging, merge your branch into it, and push with the button on the merge notice.

Nothing dangerous runs unconfirmed

Force push, hard reset, deleting an unmerged or remote branch, dropping a stash, deleting a worktree with work in it: each one first shows exactly what would be lost, and runs only against the state you were shown. If the branch, the files or the remote changed in the meantime, gg asks again.

Conflicts, one file at a time

When a merge, rebase or cherry-pick stops on conflicts, a banner shows each file's state. Resolve them in your editor, then Continue, Abort, or Skip a commit that has nothing left to apply.

Your git, on the record

gg runs the git you already have, so SSH keys, credential helpers and hooks behave as they do in your terminal. The command log lists every git command it ran, with its output.

Settings, and every shortcut on one sheet

Settings (⌘,) hold the theme, the date format, the background fetch, the editor and terminal a worktree opens in, and where new worktrees go. Press ? for the keyboard shortcuts: tabs, the graph, commits, panels and worktrees.

Light or dark, always current

Light and dark themes
The same graph in either, tuned so every lane stays readable.
Live refresh
Changes made in a terminal or an editor show up on their own, in every worktree.
Background fetch
Remote branches, and the open pull requests with them, are fetched in the background, on a schedule you can change or turn off.

Open it from your terminal

Type gg in a repository's folder and it opens in the app; give it a path to open the repository that holds it. If gg is already running, the repository opens there, as a tab.

Install the command once from gg → Install ‘gg’ Command… in the menu bar. It writes one small script, named gg, into a folder already on your PATH: no administrator rights, no edits to your shell files. If your shell already has a gg, such as Oh My Zsh's alias, the dialog says so.

Windows and Linux

Built and tested automatically with every release. Not yet used day to day.

  • Windows Download the installer for 64-bit Windows 10 and 11. It is built, and gg's tests pass, on Windows in CI. Nobody has used it there by hand yet.
  • Linux Download the .deb for Debian and Ubuntu, or the AppImage for other distributions. Both are built, and gg's tests pass, on Linux in CI. Not tried by hand yet either.

gg is used every day on macOS only, so expect rough edges on these two. Reports of what works and what does not are very welcome. Checksums for every file are on the release page.
